title: Customization

JK-UI is designed to be customized at every level — from swapping a color token to creating entirely new component variants. Because components are installed as source code (not a dependency), you have full control.

## Customization Levels

| Level | Scope | Effort |
|-------|-------|--------|
| CSS variable override | Global theme change | Minimal |
| Component `className` | Single instance | Minimal |
| `tv()` config edit | Per-component | Moderate |
| New `@utility` class | Project-wide | Moderate |
| New component variant | Project-wide | Significant |

---

## 1. CSS Variable Override (Global)

The simplest way to customize JK-UI is to override CSS variables. All design tokens use CSS variables, so you can change the entire look by overriding a few values.

### Change the primary color

```css
/* In your main CSS, after jk-ui-theme.css */
:root {
  --primary: var(--color-purple-600);
  --ring: var(--color-purple-600);
}
```

### Change border radius

Override the generic UI radius or target specific components:

```css
:root {
  --ui-radius: 0.375rem;      /* smaller corners on all ui-radius components */
  --card-radius: 0.5rem;       /* keep cards at default */
  --checkbox-radius: 0.25rem;  /* keep checkboxes small */
}
```

### Full theme override

```css
:root {
  --background: var(--color-stone-50);
  --foreground: var(--color-stone-800);
  --primary: var(--color-emerald-600);
  --muted: var(--color-stone-100);
  --border: var(--color-stone-200);
  --ui-radius: 0.25rem;
}

.dark {
  --background: var(--color-stone-950);
  --foreground: var(--color-stone-300);
  --primary: var(--color-emerald-500);
  --muted: var(--color-stone-900);
  --border: var(--color-stone-800);
}
```

## 2. Component className Override (Per Instance)

Every JK-UI component accepts a `className` prop. Use Tailwind utilities or inline CSS variables to override specific instances.

```tsx
<Button className="[--btn-solid-bg:var(--color-purple-600)] text-white">
  Custom Purple Button
</Button>
```

```tsx
<Card className="[--card-padding:2rem] shadow-xl">
  Wider padding card
</Card>
```

```tsx
<Badge className="bg-purple-100 text-purple-800 border-purple-200">
  Custom Badge
</Badge>
```

## 3. tv() Config Edit (Per Component)

Since components are installed as source files, you can edit the `tailwind-variants` configuration directly. Open `@/components/jk/{component}.tsx` and modify the `tv()` call.

### Add a new size

```tsx
// In button.tsx
const buttonVariants = tv({
  base: "btn ...",
  variants: {
    size: {
      xs: "btn-xs",
      sm: "btn-sm",
      md: "btn-md",
      lg: "btn-lg",
      xl: "btn-xl",
      "2xl": "h-14 px-6 text-base", // new size
    },
  },
})
```

### Change default variant

```tsx
defaultVariants: {
  size: "md",
  variant: "solid",
  intent: "primary", // changed from "gray" to "primary"
}
```

### Add a new radius option

```tsx
radius: {
  none: "",
  default: "rounded-lg",
  circle: "rounded-full",
  pill: "rounded-[999px] px-6", // new radius
}
```

## 4. New @utility Class (Project-wide)

Define new utility classes in your own CSS file using Tailwind v4's `@utility` directive.

```css
/* styles/custom.css */
@utility btn-gradient {
  @apply btn flex items-center justify-center;
  background: linear-gradient(135deg, var(--color-purple-600), var(--color-pink-500));
  color: white;
}
```

Then use it in any component:

```tsx
<button className="btn-gradient btn-md">Gradient Button</button>
```

### Custom UI variant

```css
@utility ui-gradient {
  @apply text-white;
  background: linear-gradient(135deg, var(--color-primary-600), var(--color-accent-500));
}

@utility ui-gradient-primary {
  --ui-gradient-bg: linear-gradient(135deg, var(--color-primary-600), var(--color-primary-400));
}
```

## 5. New Component Variant (Project-wide)

For a new variant that should work across all instances of a component, edit the `tv()` config.

### Add a new variant type

```tsx
// In button.tsx
const buttonVariants = tv({
  base: "btn inline-flex items-center ...",
  variants: {
    variant: {
      solid: "btn-solid",
      outline: "btn-outline",
      soft: "btn-soft",
      ghost: "btn-ghost",
      gradient: "btn-gradient", // new variant
    },
    intent: {
      // For gradient variant
      "purple-pink": "[--gradient-from:var(--color-purple-600)] [--gradient-to:var(--color-pink-500)]",
      "blue-cyan": "[--gradient-from:var(--color-blue-600)] [--gradient-to:var(--color-cyan-500)]",
    },
  },
})
```

## 6. Theme Preset Customization

The `jk-ui-cli setup` command generates a `jk-ui-theme.css` file. You can edit this file directly to customize your theme.

```css
/* jk-ui-theme.css — edit this file */
:root {
  /* Change any value */
  --background: var(--color-stone-50);
  --primary: var(--color-emerald-600);
  --muted: var(--color-stone-100);
  /* ... */
}
```

To switch to a different theme preset, run `jk-ui-cli setup` again and select a different theme.

## 7. Creating a Complete Custom Theme

For a full custom theme:

1. **Start with a preset**: Run `jk-ui-cli setup` and select a base theme.
2. **Override colors**: Edit `jk-ui-theme.css` to set your brand colors.
3. **Register in @theme**: Ensure your variables are in `@theme inline`.
4. **Test components**: Verify buttons, inputs, and cards look correct.
5. **Add dark mode**: Define `.dark` overrides if needed.

Example custom theme:

```css
:root {
  /* Brand */
  --primary: var(--color-violet-600);
  --primary-foreground: var(--color-white);
  --secondary: var(--color-violet-800);
  --secondary-foreground: var(--color-white);

  /* Surfaces */
  --background: var(--color-violet-50);
  --foreground: var(--color-violet-950);
  --muted: var(--color-violet-100);
  --muted-foreground: var(--color-violet-600);

  /* Borders */
  --border: var(--color-violet-200);
  --input: var(--color-violet-200);
  --ring: var(--color-violet-600);

  /* Radius */
  --ui-radius: 0.5rem;
}
```

## 8. Component Tokens Reference

Key CSS variables you can override per component:

| Component | Variables |
|-----------|-----------|
| Button | `--btn-solid-bg`, `--btn-solid-text`, `--btn-outline-bg`, `--btn-ghost-bg`, `--btn-focus-outline-color` |
| Card | `--card-padding`, `--card-radius` |
| Input | `--ui-input-place-holder`, `--ui-input-focus-outline` |
| Checkbox | `--checkbox-size`, `--checkbox-bg`, `--checkbox-bg-checked`, `--checkbox-radius` |
| Radio | `--radio-size`, `--radio-indicator-size` |
| Switch | `--toggle-width`, `--toggle-height`, `--knob-size` |
| Badge | `--ui-solid-bg`, `--ui-solid-text`, `--ui-soft-bg`, `--ui-soft-text` |
| Dropdown | `--dropdown-item-px`, `--dropdown-item-py` |

---

## Best Practices

1. **Override variables in your main CSS**, not in component files — keeps upgrades manageable.
2. **Use semantic tokens** (`--primary`, `--muted`) instead of hardcoded colors.
3. **Customize tv() configs** for project-wide component changes (sizes, variants).
4. **Use className prop** for one-off overrides.
5. **Keep `@jk-ui/base` CSS files untouched** — override in a separate CSS file.
